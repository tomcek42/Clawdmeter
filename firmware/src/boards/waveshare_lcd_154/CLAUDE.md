# LCD-1.54 — `waveshare_lcd_154`

Hardware notes for this board. Shared firmware rules are in `firmware/CLAUDE.md`.

Waveshare ESP32-S3-Touch-LCD-1.54 (ST7789, 240×240 square, CST816T touch @ 0x15). Build env: `waveshare_lcd_154`. **The first non-AMOLED port**: a plain 4-wire SPI TFT, not QSPI, and the panel has no brightness command — backlight is LEDC PWM on `LCD_BL`. **No PMU**: battery is an ADC divider on GPIO1 and `BAT_EN` (GPIO2) is a power-hold line that must be driven HIGH early in `board_init()` or the board browns out on battery. Three buttons (BOOT + GPIO5 + a PWR-role GPIO4); ES8311 chime wired up; QMI8658 (0x6B) drives auto-rotation (`LCD_AUTO_ROTATE`, default on). Unlike the CO5300 boards the ST7789 rotates in hardware: `display_hal_tick` calls `gfx->setRotation()` (MADCTL; Arduino_GFX picks the 0/80 GRAM offsets per rotation) and invalidates LVGL — no CPU pixel remap. `LCD_ROTATION` is the fixed orientation with auto-rotation off, and the calibration offset with it on; `IMU_ROT_REVERSE` flips the IMU's turning direction. `rotation.h` combines them. `touch.cpp` maps through `lcd_applied_rotation()` (what MADCTL is set to), not the IMU, so touch never runs ahead of the picture. The IMU logs `Rotation: n (ax ay az)` on serial at every change — use it to calibrate. **No boot-time orientation snap:** right after `enableAccel()` the QMI8658 returns a stale block (all axes equal, e.g. -0.83 g) and its LPF then settles over ~1 s, so a blocking boot read picks wrong/intermediate values. `imu_hal_init` leaves quadrant 0 and `imu_hal_tick`'s 400 ms hold + `read_accel` plausibility filter handle it.
